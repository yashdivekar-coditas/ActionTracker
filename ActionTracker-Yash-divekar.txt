  What you decided

  Area: Gmail
  Decision: followup writes each email itself, then runs claude -p with only
    the create-draft tool allowed, so it can never send. --dry-run prints the
    drafts instead. Recorded in ADR-0001.
  ────────────────────────────────────────
  Area: Duplicates
  Decision: Two items are the same if they have the same owner(s) and
    close-enough task wording. The latest meeting's due date wins, and every
    note an item appeared in is kept. Once an item is done it never reopens,
    and item IDs don't change when you ingest again. Recorded in ADR-0002.
  ────────────────────────────────────────
  Area: Which lines count
  Decision: Checkboxes anywhere in a note (-/*/+, nested, [x]/[X]), ACTION:
    lines, and rows of an Owner/Action/Due table. Quoted lines, code blocks
    and HTML comments are ignored.
  ────────────────────────────────────────
  Area: Ownership
  Decision: An item can have several owners, and every owner gets it in their
    follow-up. This covers "Anita & Rahul" and "Everyone"/"Team" (meaning that
    meeting's attendees). "Someone"/"TBD" items have no owner: they show in
    list --owner none and in no email. Recorded in ADR-0003.
  ────────────────────────────────────────
  Area: Same first name
  Decision: When "Priya" matches two attendees, both Priyas own it, marked as
    unconfirmed. It goes in both their drafts under "Can you confirm whether
    this is yours?". It gets narrowed to one person by a later note that names
    them ("Priya N. …") or by a new assign <id> <name> command. That makes
    five commands instead of the brief's four.
  ────────────────────────────────────────
  Area: Malformed notes
  Decision: A note is skipped and reported if it can't be read as text or has
    no readable meeting date. That covers the empty file, scratch.md,
    untitled.md and the 10-03 note ("sometime last week"). .txt files are
    never read.
  ────────────────────────────────────────
  Area: Repo
  Decision: assesment/ is now its own git repo (git init done, nothing
    committed). It contains GLOSSARY.md and docs/adr/0001–0003. I deleted the
    GLOSSARY-MAP.md I had added at the Gatepass root, so that repo is back to
    how it was.

  Defaults I filled in (say if any is wrong)

  - Stack: Python 3 standard library plus SQLite, with pytest for tests. The
    database file is .actiontrack.db. Emails come from a people.json file that
    maps names to addresses; if a person has no entry, their draft has an empty
    To.
  - Due dates: worked out from the meeting date, not today.
    - "by Friday" means the first Friday after the meeting. The data never
      actually has "Friday" written on a Friday, apart from the commented-out
      line.
    - "end of next week" means the Friday of the following week.
    - "mid-October" means the 15th.
    - "end of month" means the last day of the meeting's month.
    - "EOD" means the meeting date.
    - "next Tuesday" said on Monday 10-05 means 10-06, the first Tuesday after.
